# 0.2.0 release checklist

Use this checklist before tagging `v0.2.0`. After the tag lands, keep this file
as release evidence (same pattern as [`0.1.0-release.md`](0.1.0-release.md)).

## Preflight

- [x] `Cargo.toml` version is `0.2.0`
- [x] `CHANGELOG.md` has a dated `0.2.0` section
- [x] `docs/reports/0.2.md` describes the compatibility claim
- [x] `PARITY.md` marks 0.2 complete and points at the 0.2 inventory
- [x] `docs/ROADMAP.md` / `docs/milestones/0.2.md` exit checklist complete
- [x] ADR-007 and ADR-008 are accepted
- [x] `LICENSE-APACHE` and `LICENSE-MIT` are present
- [x] `repository` / `homepage` point at `eddiethedean/oxiland`
- [ ] Working tree is clean and pushed to `main`
- [ ] Latest CI on `main` is green (Check + Fjall + MSRV + RDF I/O conformance)
- [x] `cargo publish --dry-run` succeeds locally

## Local verification

```console
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo doc --no-deps
python3 scripts/check-inventory.py
python3 scripts/check-docs.py
scripts/generate-public-api.sh check
cargo run --example quick_start
cargo run --example contexts
cargo run --example parse_serialize
python3 compatibility/harness/oracle_smoke.py
python3 compatibility/harness/differential_smoke.py
cargo publish --dry-run
```

## Publish

```console
git tag -a v0.2.0 -m "oxiland 0.2.0"
git push origin v0.2.0
```

The Release workflow runs CI then `cargo publish` when the tag matches
`Cargo.toml`.
