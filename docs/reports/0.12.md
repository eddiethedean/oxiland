# Milestone 0.12 performance report

Status: in progress
Milestone: [`0.12`](../milestones/0.12.md)
Depends on: [`0.11`](../milestones/0.11.md) (complete)

## Summary

0.12 is the dedicated performance-optimization phase between demonstrated
Redland parity (0.11) and 1.0 readiness. The milestone outcome is a native,
revision-bound faster-than-Redland win on every required case and profile,
measured from **Cargo `--release` / production compiles**, with resource
budgets and parity retention—not a geometric-mean, debug-build, or
cherry-picked claim.

The first 0.12 landing addresses the two largest Unix cliffs without weakening
handle safety: model cardinality is cached until mutation, repeated live-handle
validation has a generation-bound fast path, and stream iteration no longer
allocates a current statement unless the caller requests it. The performance
harness now validates case outputs and `P-GRAPH-10K` executes and consumes an
actual CONSTRUCT result instead of calling the SELECT workload.

The suite and matrix remain drafts because RSS/disk budgets have not been
measured and reviewed. `scripts/check-0.12-release.py` intentionally rejects
that state, as well as stale, synthetic, dirty-worktree, incomplete, or
artifact-unbound evidence.

## Starting observations (0.11 tip)

Independent C `perf_bench` medians (`synthetic: false`) show strong Oxiland
wins on Unix mutation/parse/serialize, mixed query results, and large losses
on full-model scan and trivial C size-call overhead on macOS/Linux. Windows
is near parity on most cases. Resource budgets were intentionally empty in
the 0.11 suite. See the milestone’s “Known cliffs” table and the raw JSON
under `compatibility/qualification/performance/`.

## First local diagnostic

On the macOS Apple Silicon development host, paired `perf_bench` release
binaries showed the following approximate median throughput ratios after the
first landing. These are direction-finding measurements from a dirty
development worktree—not revision-bound qualification evidence—and therefore
do not satisfy any exit checkbox.

| Case | 0.11 native ratio | First local diagnostic | Result |
|---|---:|---:|---|
| `P-CALL-100K` | `0.007` | `0.35` | materially improved; still below `1.05` |
| `P-SCAN-10K` | `0.031` | `0.09` | improved; still below `1.05` |
| `P-GRAPH-10K` | not comparable (old harness ran SELECT) | `1.76` | corrected workload; qualification rerun required |

Command path: `compatibility/harness/c_oracle/build.sh`, followed by the
Redland and Oxiland `perf_bench --case …` binaries. Ratios are rounded because
this run is attribution evidence only; the frozen gate publishes raw samples
and bootstrap confidence intervals.

## Claims policy

Until the 0.12 exit checklist is complete, do **not** market a blanket
“faster than Redland” statement. Cite per-case ratios with host, profile,
suite revision, and confidence intervals only.
